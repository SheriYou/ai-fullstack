## 2. 项目背景

当前 Hot70 活动需要通过 H5 / 活动页承接用户流量，并进一步引导用户进入 WhatsApp 咨询、完成预订、了解权益和到店提机。

如果用户进入 WhatsApp 后完全依赖人工承接，会存在以下问题：

1. \*\*用户进线后响应不稳定，\*\*需要等待人工回复，影响活动转化效率。

2. \*\*高频问题重复消耗人工。\*\*

3. \*\*活动链路容易断点，\*\*用户从活动页进入 WhatsApp 后，如果没有及时引导，可能不知道下一步该预订、提机还是咨询人工。

因此，需要建设 Hot70 WhatsApp 机器人，优先服务 Hot70 活动首版上线，帮助用户完成基础问答、预订引导、提机引导和人工兜底。

## 3. 产品目标与指标

### 3.1 产品目标

本期目标是跑通 Hot70 WhatsApp 用户接待闭环：

- 用户发消息后，智齿 WhatsApp API 将消息同步给传音自研机器人；

- 机器人根据用户问题进行意图识别、知识库匹配和回复；

- 如需人工处理，则调用智齿在线客服接口转人工，并暂停机器人自动回复。

- 如果开发时间允许，机器人可根据用户对话内容写入客户标签，便于人工客服和运营判断用户阶段；如果时间不足，不影响首版上线。

## 5. 总体链路与系统分工

### 5.1 总体链路

用户消息链路：

> WhatsApp 用户 → 智齿 WA API → 传音机器人 → 机器人回复 / 转人工判断 → 智齿 WA API → WhatsApp 用户

转人工链路：

> 传音机器人 → 智齿在线客服接口 → 智齿客服工作台（人工回复）→ 智齿接口 → 传音机器人 → 智齿 WA API → WhatsApp 用户

### 5.2 系统分工

| 系统/角色 | 定位 | 主要职责 |

|---|---|---|

| 智齿 WhatsApp API | WhatsApp 消息通道 | 接收 WhatsApp 用户消息，提供消息发送能力 |

| 自研机器人 | 消息中枢 + 智能接待 | 接收消息、识别意图、问答、转人工判断、状态管理、日志沉淀 |

| 智齿在线客服系统 | 人工客服工作台 | 承接机器人转入的访客，由人工坐席回复 |

| 运营 | 内容提供方 | 提供 FAQ、活动规则、权益、门店、提机和人工兜底口径；规定“机器人怎么说、如何追问、如何引导转化”，说明典型场景下机器人如何连续对话 |

| 产品/测试 | 验收方 | 设计需求、测试用例、验收指标和上线风险评估 |

| 开发 | 实现方 | 完成 WA API 对接、机器人逻辑、智齿接口、日志与状态管理 |

## 6. 功能需求

### 6.1 基础意图识别

机器人需要识别用户当前问题的大致意图，用于判断应该从知识库回复、是否转人工，本期意图范围包括：

- Hot70 产品信息咨询；

- 活动规则咨询；

- 预订相关咨询；

- 提机相关咨询；

- 门店相关咨询；

- 人工客服诉求；

- 知识库无法覆盖的问题。如果用户问题不在本期范围内，机器人不应编造答案，应使用兜底话术并转人工。

### 6.2 Hot70 知识库问答

机器人回复必须遵循三个原则：

1. \*\*只基于已确认知识回复\*\*：知识库没有覆盖或业务未确认的信息，不直接编造。

2. \*\*动态信息优先转人工\*\*：库存、订单状态、门店实时现货、特殊优惠等动态信息，不用静态话术硬答。

3. \*\*未命中问题要沉淀\*\*：所有未命中、转人工问题都需要记录，作为后续补充 FAQ 的来源。

#### 6.2.1 知识库类别

| 内容 | 作用 | 维护方 |

|---|---|---|

| FAQ 知识库 | 回答“事实是什么” | 业务运营 |

| Bot 话术库 | 规定“机器人怎么说” | 私域运营 |

| 多轮问答样例 | 说明典型被动承接场景 | 私域运营 |

| 转人工规则 | 规定哪些问题不由 Bot 处理 | 产品 + 业务 |

FAQ 知识库：Hot 70 FAQ知识库

| 类别 | 需要业务提供什么 | 首版优先级 |

|---|---|---|

| Hot70 商品信息 | SKU、价格、配置、颜色、内存、电池、相机、商品状态、商品链接 | P0 |

| 活动规则 | 活动时间、活动入口、参与方式、预订流程、是否需要付款、预订后下一步 | P0 |

### 6.3 转人工

触发条件：

- 用户明确要求人工客服；

- 用户问题未命中知识库；

转人工推送字段：

| 信息 | 说明 |

|---|---|

| 用户标识 | WhatsApp 用户 ID / 手机号 |

| 最近意图 | 价格、配置、门店、分期、库存等 |

| history\_messages | 最近 N 轮关键聊天记录 |

### 6.4 人工坐席分配

智齿支持转人工时传入坐席 ID 或技能组 ID。

\*\*优先方案：传技能组 ID（已确认）\*\*

如果智齿侧已配置 Hot70 专属技能组，传音机器人转人工时优先传入技能组 ID，由智齿客服系统在技能组内完成具体坐席分配。这种方式对更简单，传音只需要判断“该用户需要转人工”，不需要自己维护每个坐席的在线状态和接待量。

### 6.4 智齿字段

| 智齿字段 | 用途 |

|---|---|

| partnerid | 用户唯一标识 |

| user\_tels | 用户手机号 |

| user\_name / user\_nick | 用户昵称 |

| groupid | Hot70 / 本地客服技能组 |

| agentid | 指定坐席，可选 |

| tran\_flag | 转人工标识 |

| params / customer\_fields | 标签、来源、状态、摘要 |

| history\_messages | 历史聊天记录 |

### 6.5 日志记录

日志主要用于排查智齿 API 对接、机器人回复、标签写入、知识库命中、转人工和人工回复回传链路。

| 字段 | 说明 | 用途 |

|---|---|---|

| session\_id | 会话 ID | 串联同一用户多轮对话 |

| wa\_id / phone | WhatsApp 用户标识 / 手机号 | 识别用户 |

| message\_time | 用户消息时间 | 计算响应耗时 |

| user\_message | 用户原始问题 | 复盘问题与补充知识库 |

| detected\_intent | 识别意图 | 判断意图识别是否正确 |

| confidence | 识别置信度，如有 | 判断低置信度兜底 |

| knowledge\_hit | 是否命中知识库 | 统计知识库覆盖率 |

| bot\_reply | 机器人实际回复内容 | 检查回复准确性 |

| customer\_tag | 本轮判断出的客户标签 | 判断标签是否正确 |

| handoff\_flag | 是否转人工 | 统计兜底与人工量 |

### 6.6 客户标签写入（P1 / 时间允许）

原方案中的“用户状态”调整为“客户标签”。该能力优先级低于消息收发、知识库问答、转人工和人工回复回传。如果开发时间允许，机器人可根据用户对话内容判断客户标签，并通过智齿“修改客户标签”API 写入智齿；如果时间不足，可以先不做，不影响 Hot70 WhatsApp Bot 首版上线。

用户标签只根据用户当前对话中明确表达的信息打标签。如果用户没有表达清楚，优先保持为“未识别 / 未更新”，不强行判断。

| 标签 | 定义 |

|---|---|

| 已预订未提机 | 已提交预订单，尚未到店提机 |

| 未预订高意向 | 未预订，但有购机相关咨询，例如配置、价格、分期、以旧换新等 |

| 未预订低意向 | 未预订，仅参与秒杀、领福利或泛活动互动，暂无明确购机咨询 |

| 已提机 | 已到店提机并完成成交 |

| 沉默未互动 | 进入私域后没有任何互动 |

\*\*标签写入方式：\*\*

1. 用户发送 WhatsApp 消息后，智齿 WhatsApp API 将消息同步给传音机器人。

2. 机器人基于用户消息和当前会话上下文判断用户标签。

3. 如果判断出明确标签，机器人调用智齿“修改客户标签”API，将对应标签写入智齿客户信息。

4. 如果后续对话出现更明确的信息，机器人可以再次调用标签 API 更新客户标签。

## 7. 测试内容与验收标准

### 7.1 测试目标

用户消息能进入机器人，机器人能基于知识库正确回复 Hot70 高频问题；

无法处理时能转人工，人工回复能回到 WhatsApp；

关键过程可通过日志追踪。

### 7.2 测试范围

1. \*\*消息收发链路\*\*：用户 WhatsApp 消息进入机器人，机器人回复能回到 WhatsApp。

2. \*\*知识库问答\*\*：Hot70 产品、活动、预订、提机、门店、权益等高频问题能基于知识库回答。

3. \*\*转人工与坐席分配\*\*：用户要求人工、未命中知识库、动态信息或异常问题能触发转人工，并按技能组或坐席规则分配。

4. \*\*人工回复回传\*\*：人工客服在智齿工作台回复后，消息能回到 WhatsApp 用户。

5. \*\*日志追踪\*\*：消息、回复、意图、知识库命中、标签、转人工、异常都能查到。

6. \*\*客户标签写入\*\*：机器人能根据用户表达写入或更新客户标签，智齿侧可查看或读取。

### 7.3 核心验收指标

| 指标 | 定义 | 建议目标 |

|---|---|---|

| 消息收发成功率 | 用户 WhatsApp 消息能被传音机器接入、机器人回复、转人工、人工回复回传链路成功的比例 | 100% |

| 回复准确率 | 回复内容与知识库、业务确认口径一致的比例 | ≥85% |

| 标签写入成功率 | 应写入标签的场景中，智齿客户标签成功写入或更新的比例 | ≥95% |

| 转人工准确率 | 应转人工的问题能正确触发人工兜底的比例 | ≥90% |

| 平均响应时间 | 用户发消息到机器人回复的平均耗时 | ≤10 秒 |
